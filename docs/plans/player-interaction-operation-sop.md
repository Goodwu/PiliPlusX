# 跨平台播放器固定操作说明

本文适用于 macOS、OHOS 以及其他带自动隐藏控制条的播放器页面。它只规定交互操作时序；不同平台的解码、渲染和 HDR 结论仍必须分别记录，不能互相外推。

## 一、统一硬规则

播放器控制条、设置菜单、质量菜单和进度条都是短时可见 UI。所有操作必须采用一个连续动作批次：

```text
唤出控制条
  → 立即点击/选择目标控件
  → 必要时连续完成下一步
  → 最后一次性读取 AX/日志/截图状态
```

禁止以下做法：

- 唤出控制条后先截图识别，再等待下一轮点击；
- 在两次点击之间重新读取 AX 树，导致控制条超时收起；
- 使用已经失效的旧坐标或旧 `element_index`；
- 以视频主体点击代替控制条唤出后，又假定播放/暂停状态没有改变；
- 只因为控制条显示“杜比”或“HDR”就推断实际解码和显示输出。

如果一批操作失败，重新执行完整批次：重新唤出 → 立即操作 → 最后读取；不对已收起的 UI 继续补点。

## 二、固定批次模板

### 1. 搜索

```text
进入搜索页
→ 点击输入框本体
→ 全选
→ 输入目标 BV/关键词
→ 立即读取输入框文本
→ 文本正确后立即点击搜索
→ 最后读取结果
```

搜索文本未写入时，不得点击搜索按钮；重新执行整个批次。

### 2. 设置菜单

```text
控制条已可见时
→ 立即点击“更多/设置”
→ 立即点击目标菜单项
→ 必要时立即点击二级选项
→ 最后读取菜单结果和播放器状态
```

如果控制条已经收起，不要直接点击旧的设置坐标；重新唤出控制条后从第一步开始。

### 3. 进度条

优先使用当前 AX 树中仍有效的进度条控件；如果 AX 不支持 seek，使用同一截图中的坐标，并在同一连续调用中完成：

```text
唤出控制条
→ 立即点击进度条目标位置
→ 最后读取 position/duration
```

不要在“唤出控制条”和“点击进度条”之间截图或等待。若第一次点击视频主体造成播放/暂停切换，不得把它当作成功 seek；下一批次必须重新确认控制条和播放状态。

### 4. 播放控制

```text
唤出控制条
→ 立即点击播放/暂停/全屏/换源目标
→ 必要时连续完成确认动作
→ 最后读取播放位置、窗口状态和可见帧
```

## 三、Computer Use 调用约束

- AX 调用使用 `element_index`，不能写成 `element`。
- `element_index` 只在最近一次状态读取后有效；状态变化后必须重新获取。
- 坐标操作只能依据刚刚取得的同一截图，不能跨轮次复用。
- 连续动作批次中不插入截图、长等待、重新查询或焦点切换。
- 批次结束后才允许截图和读取完整 AX 树，作为结果证据。

## 四、平台隔离

### macOS

记录页面层、解码层、native output 层和实际可见帧；窗口/控制条操作不能替代 EDR、色彩空间或 headroom 证据。具体 DV 流程见 [macOS 产品 DV/HDR 固定测试操作说明](macos-product-dv-test-sop.md)。

### OHOS

记录 Flutter 控件、XComponent/native Surface、HAP 日志和真实设备/模拟器画面；native Surface 与 Flutter overlay 可能有独立的交互边界，控制条动作必须在同一批次完成。OHOS 的“仅软件解码、仅 RGBA 显示”能力边界不能被 macOS 结果覆盖。

控制条无法由视频主体点击唤出时，按以下事件链定位首个断点：

```text
Flutter pointer route
→ MouseInteractiveViewer Listener
→ _onPointerDown
→ tap recognizer / gesture arena
→ _onTapUp
→ showControls
→ 控制条合成
```

实体机应使用同一个 pointer 分别点击视频中心、上下黑边，并记录
`down/move/up/cancel`、surface bounds、surface ID/generation 和 HDR 输出状态。已有
的 opaque Listener、ArkUI `HitTestMode.None`、SurfaceView/HCPP A/B 结果必须作为证据
记录，不能直接继续叠加重复 Listener 或调低手势阈值。

HDR 是硬约束。排查交互问题时不得关闭 native surface/HCPP、降低 HDR 片源选择、或
切换到 SDR tone-map。若确认事件没有进入 Flutter，修复层级应在 OHOS PlatformView
的命中与事件转发；若事件已进入 Flutter，再调整交互层和 recognizer 的边界。任何
交互修复都必须重新验证 HDR native output、可见帧以及控制条行为。
